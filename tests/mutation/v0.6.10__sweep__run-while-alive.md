## Survivor triage

All three survivors are **killable** -- none is equivalent or don't-care.

- **M-1** (idle=0 semantics untested): `Request.idle` defaults to 180, never 0, and no test anywhere in the swept suite constructs a call with `idle=0`. The `req.idle and` guard exists specifically so `idle=0` disables the silence check the same way `timeout=0` (already tested) disables the ceiling -- but that symmetry had no test of its own. **Killer test written**: `test_an_idle_of_zero_means_no_silence_limit_v0610_M1` in `tests/test_transport_cli.py` (uses `--mute` with `timeout=1, idle=0`; asserts the call is cut by the ceiling, not falsely declared dead).
- **M-4** (`reversed()` unexercised): the `stream-json` fixture never emitted more than one `type=="result"` event, so forward and backward search were indistinguishable. **Killer test written**: `test_a_stream_json_locator_with_two_result_events_takes_the_last_v0610_M4`, plus a new `--events-twice` branch added to the shared `FAKE_CLI` fixture script in `tests/test_transport_cli.py` that emits an early spurious (non-JSON-payload) result event followed by the real one.
- **M-10** (Progress tool-call heuristic too permissive): the only test line combining `"tool_use"` and `"assistant"` always had both, so AND vs. OR was never distinguished. **Killer test written**: `test_the_progress_sink_does_not_count_plain_assistant_text_as_a_tool_call_v0610_M10` in `tests/test_aistep.py` (a line with `"assistant"` but no `"tool_use"` must not increment `tool_calls`).

Each killer test was demonstrated both ways per the skill's close-the-loop rule: it fails (red) when its mutant is re-applied, and passes (green) on the restored real code.
