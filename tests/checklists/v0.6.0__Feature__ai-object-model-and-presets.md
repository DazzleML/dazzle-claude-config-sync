## What this is

The previous checklist for `--ai` (`v0.6.0__Feature__merge-ai-pass-1.md`) walked the feature: the prompt, the proposal, the record, the rules, the copy rule, the accept gate. This one covers what changed underneath it on 2026-09-05: a backend is now a *preset* over one of three transports (a CLI subprocess, an OpenAI-compatible server, a prompt written to a file); local versus remote is an address and a key rather than different code; `ccs doctor` builds the configured preset and prints what it says about itself; the merge report says which model actually answered; and the record beside a proposal is shaped for several answers. It also carries the only tests that matter for the goal this work serves -- **real merges through claude, codex, lmstudio and openrouter, judged by a person or against the golden set** -- because no automated test in this repo asks a real model.

Run it after the automated suite is green. Sections 1-4 are cheap and deterministic; Section 5 costs money or needs a server and is the point.

## Prerequisites

1. Windows, macOS or Linux with Python 3.12, git, and this worktree installed in editable mode -- or simply run from the worktree root with it first on the path:

   **cmd.exe**: `set PYTHONPATH=%CD%` &nbsp; **PowerShell**: `$env:PYTHONPATH = $PWD` &nbsp; **POSIX**: `export PYTHONPATH="$PWD"`

   Then `python -m dazzle_claude_config` is `ccs` for every command below. (Anywhere else, `ccs` may resolve to an older installed build that has none of this; the previous checklist lost a session to exactly that.)
2. **A scratch world, never your real config.** `python tests/one-offs/thinking/build_ai_world.py <dir>` builds a checkout, a live tree and a user directory with one conflicting file (`skills/s.md`) and prints the three `--checkout-dir` / `--claude-dir` / `--user-claude` overrides to pass to every `ccs` command. Every step below assumes those three flags; they are written as `<world flags>`. Nothing here touches `~/.claude` or `~/claude`.
3. For Section 5: LM Studio installed with a model downloaded (the runs below were made with a Qwen 3.8 27B); a Claude Code CLI login; an OpenRouter account and key; the Codex CLI if it runs on your box (on the box this was built on it does not -- see 5.4).
4. **Scratch-git rules** if you make your own fixtures: every git command carries `-C <scratch path>`, and every commit carries `-c user.email=test@example.com -c user.name=test -c commit.gpgsign=false -c tag.gpgsign=false`. Never change global git config; per-invocation `-c` only. (On a box with global signing, a bare `git commit` in a scratch repo fires a GPG dialog for a commit you did not mean to sign.)
5. Reset between sections: delete the world directory and rebuild it. Nothing outside it changes.

## High-Value Verification (~5 minutes, no model needed)

**If you only have 5 minutes**, run these five. They prove the seam is one seam.

### HV.1 -- doctor asks the backend, whatever it is

Validates: doctor builds the configured preset and prints what `probe()` says; no branch on a backend's name.

- [ ] **Steps** (pick your shell; `<world flags>` from the prerequisites):

  **cmd.exe**
  ```cmd
  set CCS_AI_MERGE_BACKEND=lmstudio
  python -m dazzle_claude_config <world flags> doctor | findstr "ai merge"
  set CCS_AI_MERGE_BACKEND=openrouter
  python -m dazzle_claude_config <world flags> doctor | findstr "ai merge"
  set CCS_AI_MERGE_BACKEND=claude
  python -m dazzle_claude_config <world flags> doctor | findstr "ai merge"
  set CCS_AI_MERGE_BACKEND=
  ```
  **PowerShell**
  ```powershell
  $env:CCS_AI_MERGE_BACKEND = "lmstudio";   python -m dazzle_claude_config <world flags> doctor | Select-String "ai merge"
  $env:CCS_AI_MERGE_BACKEND = "openrouter"; python -m dazzle_claude_config <world flags> doctor | Select-String "ai merge"
  $env:CCS_AI_MERGE_BACKEND = "claude";     python -m dazzle_claude_config <world flags> doctor | Select-String "ai merge"
  Remove-Item Env:\CCS_AI_MERGE_BACKEND
  ```
  **POSIX**
  ```bash
  CCS_AI_MERGE_BACKEND=lmstudio   python -m dazzle_claude_config <world flags> doctor | grep "ai merge"
  CCS_AI_MERGE_BACKEND=openrouter python -m dazzle_claude_config <world flags> doctor | grep "ai merge"
  CCS_AI_MERGE_BACKEND=claude     python -m dazzle_claude_config <world flags> doctor | grep "ai merge"
  ```
- [ ] **Expected:** with the LM Studio server *not* running: `ai merge backend lmstudio: no model server at http://127.0.0.1:1234/v1 -- start the local server (in LM Studio: the Developer tab) or point at another endpoint -- ...`. With no key exported: `ai merge backend openrouter: OPENROUTER_API_KEY is not set in the environment -- openrouter needs a key there -- ...`. With the Claude CLI installed: `ai merge backend claude: its CLI was found: <path> -- your text goes to a hosted model`.
- [ ] **Why this matters:** three kinds of backend, one sentence shape each, and the sentence names the thing to fix -- a server to start, a variable to set, an executable to install. If doctor cannot tell them apart without a name table, the seam is not one seam.

### HV.2 -- a canned answer still becomes a proposal

Validates: the whole pipeline from answer to proposal, through the new caller, with no backend involved.

- [ ] **Steps** (cross-shell; the answer file is plain JSON):
  1. Write `answer.json` in the world directory: `{"hunks": [{"hunk": 1, "lines": ["T1"], "rules": [], "rationale": "upstream"}]}`
  2. `python -m dazzle_claude_config <world flags> merge skills/s.md --ai --ai-response answer.json --no-launch`
- [ ] **Expected:** `staged skills/s.md -- the AI's proposal (prompt-only) at <...>.merged-ai; validation passed; nothing installed`, and the proposal's bytes equal the payload's side.
- [ ] **Why this matters:** every later step assumes this floor; if the rewired caller broke assembly, nothing in Section 5 is worth running.

### HV.3 -- the golden set is coherent

Validates: the nine fixtures assemble to their own expected text in canned mode.

- [ ] **Steps** (cross-shell): `python -B -m pytest -q -p no:cacheprovider tests/test_golden_ai_merge.py`
- [ ] **Expected:** `11 passed, 9 skipped` -- the nine skips are the live mode, which HV.5 and Section 5 unlock.
- [ ] **Why this matters:** the golden set is the standard the real backends are judged against; a fixture that cannot pass with its own answer cannot judge anyone.

### HV.4 -- nothing in the vendored tree knows this tool

Validates: purity (no host token under `_vendor/`), and the reverse -- only one module imports it.

- [ ] **Steps** (cross-shell): `python -B -m pytest -q -p no:cacheprovider tests/test_vendored_ailib.py tests/test_compat_markers.py`
- [ ] **Expected:** `8 passed`. The compat inventory names exactly two remnants: the `analyze()` wrapper and the schema-1 record loader.
- [ ] **Why this matters:** the tree is meant to become the shared library; the purity test is what makes that a copy rather than a rewrite, and the inventory is what stops "temporary" from becoming permanent.

### HV.5 -- one real merge through a local model

Validates: the north star's first leg, on your own hardware. (Needs LM Studio's server running with a model loaded -- Section 5.1 has the setup.)

- [ ] **Steps**:
  1. Start LM Studio's server (Developer tab, *Start Server*) with a model loaded.
  2. Rebuild the world; `python -m dazzle_claude_config <world flags> merge skills/s.md --ai lmstudio --no-launch --ai-refresh`
- [ ] **Expected:** a `staged` line, then `answered by <the model id> via openai_compat|http://127.0.0.1:1234/v1|...; model, schema` on the next line, then the rationale the model gave. 30-60 s on a 27B model.
- [ ] **Why this matters:** the plan says "the pipe works" is not "the results are reasonable"; this is the first result you judge.

### 2.5 A broken or missing vendored copy

*(Added 2026-09-05, run-02 -- a seam the checklist named ("doctor with a broken vendored copy") without a step; the run found it FAILS.)*

- [ ] **Steps:** copy the package to scratch, corrupt or delete `_vendor/ailib/types.py` (or any module `_vendor/ailib` transitively needs), clear `__pycache__`, then run `doctor` (or any `ccs` verb) against that copy.
- [ ] **Expected (per `cli.py`'s own comment at the ai-merge block):** a graceful `[WARN] ai merge library: <error> -- the vendored copy under _vendor/ailib is missing or broken; even prompt-only cannot run`, with the rest of `doctor` still running.
- [ ] **Observed (run-02, FAIL):** the whole CLI crashes with an unhandled `ImportError`/traceback before argument dispatch, and `doctor` never runs at all. `ailib` is imported unconditionally at CLI module-load time (`cli.py` imports `merge`, `merge.py` imports `aistep`, `aistep.py` imports `ailib`, `ailib.py` imports `_vendor.ailib.backend` -- all at module scope, none lazy), so by the time `_doctor()`'s own `try: from . import ailib as _ailib / except Exception` runs, the module is already cached in `sys.modules` (if it survived import) or the process already crashed (if it didn't). The try/except at `cli.py` around the ai-merge block cannot be reached by an import-time failure in `_vendor/ailib` -- only by a failure inside a function call made after a successful import. This is a diagnosis, not a fix; see the run-02 results file for the full repro and traceback.

### 3.5 The classification counts line, and one-sided edits that never reach the model

*(Added 2026-09-05, run-02 -- fraction #19's automated twin is `tests/test_merge_ai.py::test_the_counts_come_first_and_one_sided_lines_never_reach_the_prompt`; this is its hand-run.)*

- [ ] **Steps:** build a twenty-line file where ours alone rewrote line 2, theirs alone rewrote line 18, and both rewrote line 10 (diff3 resolves the two one-sided edits itself, leaving exactly one hunk). Run `merge <file> --ai prompt-only --no-launch`.
- [ ] **Expected:** the first line under `prompt written <file>` reads `hunks: 1 both sides changed -- the model's; 19 lines git resolved on its own, never sent`. The written prompt (`<user dir>/ccs-merge-rules/_prompts/*.md`) contains the one hunk's own lines but neither `OURS ALONE` nor `THEIRS ALONE` -- the one-sided edits never reach the model.
- [ ] **Check:** answer the hunk and stage it (`--ai-response` with `"lines": ["T1"]`); the merged result contains BOTH one-sided edits (git resolved them on its own) alongside the model's choice for the shared hunk.
- [ ] **Check:** the same written prompt contains both the paragraph rule and the additions rule verbatim (`hunk marked **paragraph**` / `hunk marked **additions**` -- see `dazzle_claude_config/prompts/ai-merge.md`), and the drop-rule sentence (`selecting a side is not a drop`) -- the template's rules render into every prompt, not only the ones whose hunk kind they describe.
- [ ] **Why this matters:** the same criterion the golden set and #19 exist for -- the model must see only what it is being asked to resolve, and the counts must say so before anything else about the file.

### 3.6 A deep checkout path does not lose its common ancestor

*(Added 2026-09-05, run-02 -- automated twin `tests/test_base_inference.py::test_infer_base_survives_a_deep_checkout_path`; the fourth finding from the maintainer's run-01 lmstudio pass, reproduced here by hand.)*

- [ ] **Steps:** build a checkout whose absolute path is 198 characters long (pad a directory name to reach it), with a tracked file whose own name is about 50 characters, two commits (the second changing one line), and a live edit to the same line. Keep the checkout at or below 207 characters -- git itself cannot write objects past that on Windows -- and keep `--user-claude` at an ORDINARY short path (nesting the workspace under the same padded parent adds enough length to its own `.merged.inputs/*` files to hit the plain Windows 260-character path limit, which is a different, unrelated ceiling from the one this step tests). Run `merge <file> --ai prompt-only --no-launch`.
- [ ] **Expected:** the base is found and the merge proceeds to exactly one reported conflict hunk -- NOT `no common ancestor: a two-way guess is not a merge`. (Before the fix, every `git show <40-hex-sha>:<path>` in `infer_base`'s candidate search failed with Windows' `Filename too long` at this depth -- git stats the `<sha>:<path>` argument as a file before treating it as a revision -- and every candidate was skipped.)
- [ ] **Why this matters:** the real workspace's own paths run this deep on some boxes; a silent `no common ancestor` reads as "there is no shared history" when the true cause is a path-length quirk in the candidate search, not the repository.

## Section 5: real merges -- the north star (~30-60 min, money and servers)

### 5.2 claude (the Claude Code CLI; ~$1.27 per call on a box with a large global CLAUDE.md)

- [ ] **Steps:** as 5.1 with `--ai claude` and `CCS_GOLDEN_AI=claude`. Budget: the single run plus nine fixtures is about ten calls.
- [ ] **Expected:** the same matrix; claude matched the first fixture in three live runs before this slice, and once justified its choice from the ancestry dossier. Note the `answered by` line names no model (the text-mode CLI does not report one) unless `ai_merge_model` was set.

### 5.3 openrouter (the "out the gate" hosted provider; pennies per call)

- [ ] **Steps:** export `OPENROUTER_API_KEY`; set `ai_merge_model` to a model that honours JSON schema (OpenRouter's model page says which; a mid-size instruct model is a safe first choice); run as 5.1 with `--ai openrouter`.
- [ ] **Expected:** the matrix. A model that does not honour `response_format` answers with `openrouter.ai answered HTTP 400: <its own words>` and no retry -- switch models rather than expecting ccs to strip the schema.
- [ ] **Check:** `answered by <the routed model id> via openai_compat|https://openrouter.ai/api/v1|<model>||key:OPENROUTER_API_KEY; model, schema`.

### 5.4 codex (once its CLI runs)

- [ ] **Precondition:** `codex --version` and `codex exec --help` succeed. On the box this slice was built on, both installed builds fail with `unknown variant 'max'` (the CLI cannot parse its own server's model list); ccs reports that as `ai failed ... exited with code ...` with the full output in `<workspace>/<label>.ai-work/backend-error.txt`, which is the correct behaviour and not a pass.
- [ ] **Steps:** as 5.1 with `--ai codex`; optionally `--ai codex-strict` (the answer is read from the file `-o` writes).
- [ ] **Expected:** the matrix. If the CLI stays broken, the same models are reachable through the `openai` preset with an OpenAI key -- codex-the-model rather than codex-the-CLI; whether that satisfies the goal is the maintainer's call.

### 5.5 Reading the matrix together

- [ ] **Steps:** put the four results files side by side.
- [ ] **Expected:** for each fixture, which backends matched. The pattern -- not any single cell -- is what "reasonable results" means: a shape every backend gets right is settled; a shape only the large models get right says what a local model needs a rule for; a shape nobody gets right is a prompt problem, not a model problem.

## What the automated tests DON'T cover

- **A real model, anywhere.** Every transport test runs against a fake server on loopback or a fake CLI script. Whether claude, codex, a local Qwen or an OpenRouter-routed model produces a *reasonable* resolution is Section 5 and nothing else.
- **The real CLIs' argv.** The claude preset's argv is what three live runs proved before this slice; the codex preset's is from `codex exec --help` because the CLI does not run here. `claude-strict` and `codex-strict` are unmeasured.
- **A real server's quirks beyond the measured ones.** LM Studio's 400 on `json_object`, its empty-content-on-200 and its native load-state endpoint are in the fakes because they were measured; Ollama and OpenRouter have not been measured through this code.
- **Cost and speed.** The claude CLI's per-call price on a box with a large global `CLAUDE.md`, and a local model's minutes-versus-seconds depending on its window, are felt, not asserted.
- **Doctor's wording read as a person reads it** -- whether the sentence sends you to the right thing to fix.
- **The origin's caller** (`wtf locked`) against the real copied tree -- Section 4.
- **Windows shims** beyond one synthetic `.CMD` test; the WinGet and npm shim paths for codex are exercised only when codex is installed that way.
